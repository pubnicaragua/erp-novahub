1.3 Corregir Error Path en GET Query

Archivo: SolicitudesPagoRRHHView.tsx (Linea 300)

El componente muestra un mensaje generico y descarta el error real de la API. Se cambia para mostrar el error especifico:

Antes (error generico)

{query.isError && (
  <div className="...">
    No se pudieron cargar las solicitudes.
    Revisa tu acceso a Contabilidad.
  </div>
)}

Despues (error real de la API)

{query.isError && (
  <div className="...">
    {query.error?.message ||
     'No se pudieron cargar. Verifica permisos.'}
  </div>
)}

1.4 Limpiar Codigo Muerto (Axios Pattern)

Archivo: SolicitudesPagoRRHHView.tsx (Linea 174)

El patron error?.response?.data?.message es de Axios pero la app usa fetch. Esa propiedad siempre es undefined. Se simplifica:

Antes (dead code)

const message =
  error?.response?.data?.message ||
  error?.message ||
  'No se pudo completar.';

Despues (limpio)

const message =
  error?.message ||
  'No se pudo completar.';
Resultado esperado
Despues de esta fase, un usuario sin permisos vera: "Acceso denegado. No tienes el permiso de enviar requerido para Recursos Humanos o Nomina o Capacitaciones o Beneficios." en vez de "Cannot POST /api/hr/payment-requests".

FASE 2 - Arquitectura Grupo Empresarial / Sucursales

Decisiones de la reunion - 18 de Agosto 2026
1. Grupo = Tenant padre: Un ClientTenant "padre" con multiples ClientTenant "hijos" (sucursales). El padre no factura, solo administra.
2. Inventario por sucursal: Cada sucursal tiene sus productos y bodegas independientes.
3. Manager solo lectura + reportes: El manager del grupo ve datos consolidados pero no opera directamente en las sucursales.
4. Clientes separados: Cada sucursal tiene su propia base de clientes aislada.

2.1 Schema: Jerarquia Padre-Hijo en ClientTenant

Archivo: BackendERPNH/prisma/schema.prisma

Se agrega campo parentTenantId al modelo ClientTenant:

Campo NuevoTipoDescripcion
parentTenantIdString?FK al tenant padre (Grupo Empresarial)
parentTenantClientTenant?Relacion inverse al padre
childrenClientTenant[]Relacion a tenants hijos (sucursales)

Un Grupo Empresarial es un ClientTenant sin parentTenantId (es raiz). Una Sucursal es un ClientTenant con parentTenantId apuntando al grupo. El campo es nullable para compatibilidad con tenants existentes.

Migracion SQL idempotente:

ALTER TABLE "ClientTenant"
  ADD COLUMN IF NOT EXISTS "parentTenantId" UUID;

ALTER TABLE "ClientTenant"
  ADD CONSTRAINT IF NOT EXISTS
  "ClientTenant_parentTenantId_fkey"
  FOREIGN KEY ("parentTenantId")
  REFERENCES "ClientTenant"("id")
  ON DELETE SET NULL;

2.2 Guard de Acceso Cruzado para Managers

Archivo nuevo: BackendERPNH/src/common/guards/tenant-scope.guard.ts

Guard/middleware que permite a usuarios del tenant padre acceder a datos de tenants hijos (solo lectura):

  • Si el usuario es SUPER_ADMIN → acceso total (ya existe)
  • Si el usuario tiene parentTenantId === null (es grupo) → puede leer datos de sus children
  • Si el usuario es un tenant normal → solo su propio clientTenantId (ya existe)

Responsabilidades del guard:

  • Verificar que el usuario tenga role admin o manager en el tenant padre
  • Permitir queries con ?tenantId=xxx donde xxx es un child del tenant padre
  • Bloquear escritura (solo GET permitido para datos cruzados)
  • Registrar auditoria de acceso cruzado

2.3 Endpoint de Dashboard Consolidado

Endpoint: GET /api/tenants/group-dashboard?period=month

Retorna KPIs agregados de todos los tenants hijos del grupo:

KPIDescripcionCalculo
Total IngresosSuma de ingresos de todas las sucursalesSUM(income.amount) por tenant hijo
Total GastosSuma de gastos de todas las sucursalesSUM(expense.amount) por tenant hijo
Total OrdenesOrdenes de venta del mesCOUNT(sale) por tenant hijo
Inventario TotalUnidades en stock globalesSUM(inventoryLevel.quantity)
Top ProductosProductos mas vendidos (agregados)JOIN saleItem + product
Alertas StockProductos con stock bajo por sucursalinventoryLevel WHERE quantity < minStock
Ranking SucursalesSucursales ordenadas por facturacionORDER BY ingresos DESC

Metodo en tenants.service.ts:

async getGroupDashboard(parentTenantId: string, period: string) {
  // 1. Buscar todos los ClientTenant donde parentTenantId = X
  const children = await this.prisma.clientTenant.findMany({
    where: { parentTenantId },
    select: { id: true, name: true },
  });

  // 2. Para cada hijo, ejecutar la logica de getDashboard()
  const results = await Promise.all(
    children.map(child => this.getDashboard(child.id, period))
  );

  // 3. Agregar resultados en un dashboard consolidado
  return {
    kpis: this.aggregateKpis(results),
    branches: results.map((r, i) => ({
      tenantId: children[i].id,
      name: children[i].name,
      ...r.kpis,
    })),
    topProducts: this.mergeTopProducts(results),
    alerts: this.mergeAlerts(results),
  };
}

2.5 Transferencias Inter-Sucursal

Archivo: BackendERPNH/prisma/schema.prisma

Se extiende el modelo Transfer para soportar transferencias entre tenants:

Campo NuevoTipoDescripcion
interTenantTransferIdString?ID del transfer espejo en el otro tenant
sourceTenantIdString?Tenant origen (transferencias inter-tenant)
destTenantIdString?Tenant destino (transferencias inter-tenant)

Logica de transferencia inter-sucursal:

1
Usuario en Sucursal A crea transferencia hacia Sucursal B
2
Se crean DOS registros Transfer:
- En Sucursal A: fromId=warehouse_A, status=COMPLETED, tipo OUT
- En Sucursal B: toId=warehouse_B, status=PENDING, tipo IN
- Ambos vinculados por interTenantTransferId
3
Al completar la transferencia en Sucursal B:
- Se decrementa stock en Sucursal A
- Se incrementa stock en Sucursal B
- Se generan asientos contables en ambas sucursales

Endpoint nuevo:

POST /inventory/transfers/inter-tenant

Body:
{
  sourceTenantId: "tenant-A",
  destTenantId: "tenant-B",
  fromWarehouseId: "warehouse-A",
  toWarehouseId: "warehouse-B",
  items: [{ variantId: "...", quantity: 10 }],
  notes: "Transferencia mensual"
}

2.6 Vista Manager del Grupo Empresarial

Archivo nuevo: GroupManagerDashboard.tsx

Componente principal que muestra:

  • Header: Nombre del grupo empresarial + selector de periodo
  • KPIs consolidados: 4 tarjetas (Ingresos Totales, Gastos, Ordenes, Margen)
  • Tabla de sucursales: Nombre, Ingresos, Ordenes, Stock Bajo, Estado
  • Grafico de barras: Ingresos por sucursal
  • Top productos agregados: Los mas vendidos en todo el grupo
  • Alertas consolidadas: Productos sin stock, stock bajo por sucursal
  • Detalle de sucursal: Al hacer clic, muestra dashboard individual (read-only)

3.1 Migracion Prisma Idempotente

La migracion usa IF NOT EXISTS para ser idempotente y segura:

-- Agregar parentTenantId
ALTER TABLE "ClientTenant"
  ADD COLUMN IF NOT EXISTS "parentTenantId" UUID;

ALTER TABLE "ClientTenant"
  ADD CONSTRAINT IF NOT EXISTS
  "ClientTenant_parentTenantId_fkey"
  FOREIGN KEY ("parentTenantId")
  REFERENCES "ClientTenant"("id")
  ON DELETE SET NULL;

-- Agregar campos de transfer inter-tenant
ALTER TABLE "Transfer"
  ADD COLUMN IF NOT EXISTS "interTenantTransferId" TEXT;

ALTER TABLE "Transfer"
  ADD COLUMN IF NOT EXISTS "sourceTenantId" TEXT;

ALTER TABLE "Transfer"
  ADD COLUMN IF NOT EXISTS "destTenantId" TEXT;

3.4 Build Frontend

cd erp-novahub/novahub-frontend && npm run build
